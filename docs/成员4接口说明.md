分支：`member4`

## 一、通用约定

- 认证复用成员 3 的服务端会话：登录后带 `session_id`（HttpOnly）与 `csrf_token` Cookie。
- 所有写接口（POST/PUT/DELETE）必须带 `X-CSRF-Token`，值与 `csrf_token` Cookie 一致；
  缺失或错误返回 `403 {"detail":"缺少 CSRF 令牌"}`。
- 错误统一返回 `{"detail": "可直接展示的原因"}`。
- 未登录 `401`；角色不符或不属于本人数据 `403`；对象不存在 `404`；业务规则拒绝 `409`；
  参数或取值非法 `422`。
- 所有查询接口的过滤参数都是**可选**的，省略时使用合理默认值，不会因为漏传而返回 422。
- 所有响应根节点都是 **object**，不返回裸数组。

访问路径分两套，字段含义相同，调用方按自己的场景选择：

| 路径风格 | 用途 | 字段特点 |
| --- | --- | --- |
| `/api/v1/teacher/offerings/...` | REST 风格，供联调与后续扩展 | 字段直接对应数据模型 |
| `/api/v1/teacher/{claimable-sections,my-sections,sections/...}` | 页面兼容层 | 字段与成员 2 模板既有用法一致 |

## 二、教师授课接口

| 接口 | 权限 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| `GET /api/v1/teacher/me/qualified-courses` | 教师 | 无 | `{"courses":[{"course_id","course_code","course_name","fee"}]}` |
| `GET /api/v1/teacher/offerings/claimable` | 教师 | `semester_id?` 省略时用当前开放学期 | `{"semester_id","offerings":[班次]}` |
| `GET /api/v1/teacher/offerings/mine` | 教师 | `semester_id?` | `{"offerings":[班次]}` |
| `GET /api/v1/teacher/gradable-sections` | 教师 | 无 | `{"semester_id","semester_code","offerings":[页面班次]}`，学期为**上一已完成学期** |
| `POST /api/v1/teacher/offerings/{id}/claim` | 教师 + CSRF | 无 | `{"message","offering_id","teacher_id"}` |
| `POST /api/v1/teacher/offerings/{id}/release` | 教师 + CSRF | 无 | 同上，`teacher_id` 为 `null` |
| `GET /api/v1/teacher/offerings/{id}/roster` | 教师（仅本班） | 无 | `{"offering":班次,"students":[{"student_id","student_number","name","enrolled_at"}]}` |
| `GET /api/v1/teacher/offerings/{id}/grades` | 教师（仅本班） | 无 | `{"offering","semester_status","editable","students":[{"student_id","student_number","name","value","updated_at","updated_by"}]}` |
| `PUT /api/v1/teacher/offerings/{id}/grades` | 教师 + CSRF | `{"grades":[{"student_id","value"}]}` | `{"offering_id","updated","unchanged","changes":[]}` |
| `GET /api/v1/teacher/offerings/{id}/grade-changes` | 教师（仅本班） | `student_id?` | 见第五节 |

`班次`（REST）字段：
`offering_id / semester_id / course_id / course_code / course_name / fee / section_number /
status / capacity / enrolled_count / teacher_id / is_claimed_by_me / slots[{weekday,start_period,end_period}]`。

教师授课规则：

- 只能认领**具备资格**的课程班次；无资格 `403`。
- 已被其他教师认领的班次不能抢占；同一教师同学期上课时间重叠不能认领（`409`）。
- 重复认领自己已承担的班次按幂等处理，返回成功且不改数据。
- 学期关闭后不能认领、取消或录入成绩（`409`）。
- 花名册与成绩单只统计**已提交且未删除**方案中的正式选课记录，只允许访问本人承担的班次。

## 三、教师页面兼容接口

成员 2 模板原先调用的模拟接口已替换为下列真实实现，**路径不变**：

| 接口 | 说明 |

| `GET /api/v1/teacher/claimable-sections` | `{"semester_id","offerings":[{"id","course_code","course_name","fee","capacity","enrolled_count","section_number","semester_id","schedule_time","teacher_id","is_mine","status"}]}` |

| `POST /api/v1/teacher/sections/{id}/claim` / `unclaim` | 认领 / 取消，返回 `{"message","section_id","teacher_id"}` |
| `GET /api/v1/teacher/sections/{id}/roster` | `{"offering_id","course_code","course_name","students":[{"student_id","student_number","full_name","enrolled_at"}]}` |
| `GET /api/v1/teacher/sections/{id}/grades` | `{"offering_id","semester_status","editable","students":[{"student_id","student_number","full_name","value","updated_at","updated_by"}]}` |
| `POST /api/v1/teacher/sections/{id}/grades` | 与 PUT 版本同为成绩入口，额外返回 `message` |
| `GET /api/v1/teacher/sections/{id}/grade-changes` | 与 REST 路径返回完全一致 |

`schedule_time` 由班次时段生成，例如「周一 1-2节、周三 3-4节」。
模型里没有学分与教室字段，模拟接口原有的 `credits`、`classroom` 已删除，不凭空返回。

| 接口 | 权限 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| `GET /api/v1/student/me/grades` | 学生 | `semester_id?` | `{"student_id","student_number","semester_id","grades":[{"semester_id","semester_code","course_id","course_code","course_name","offering_id","section_number","value","passed"}]}` |

## 五、成绩变更记录（查询与验证说明）

### 5.1 写入规则

`PUT|POST /api/v1/teacher/.../grades` 的请求体：

```json
{"grades": [{"student_id": 1, "value": "A"}, {"student_id": 2, "value": null}]}
```

- 空字符串与 `null` 都表示留空；非空时必须是 `A`–`F`/`I`，否则 `422`。
- 只有**已完成学期**可以录入，否则 `409`。
- 只能为本班次正式选上的学生录入（`403`），同一学生一次只能提交一条（`422`）。
- 先整批校验再写入：任何一条不合法都不会留下半完成数据。
- **首次录入、修改、留空都会追加一条变更记录**，含变更前后值、操作教师与时间；
  重复提交相同成绩视为幂等，不产生多余记录。
- 旧版模拟接口的 `{"student_id": 1, "score": 92}` 会被拒绝（`422`），避免被当成"留空"而静默清空成绩。

### 5.2 查询接口

`GET /api/v1/teacher/offerings/{id}/grade-changes?student_id=` 与
`GET /api/v1/teacher/sections/{id}/grade-changes?student_id=`：

```json
{
  "offering_id": 1,
  "course_code": "DEMO101",
  "course_name": "软件工程导论",
  "student_id": null,
  "total": 2,
  "changes": [
    {"change_id": 2, "student_id": 1, "student_number": "20260001", "student_name": "林航",
     "previous_value": "A", "new_value": "D", "changed_by_teacher_id": 4,
     "changed_by": "教师姓名", "changed_at": "2026-10-07T07:45:49.725298"}
  ]
}
```

返回按时间**倒序**（最新在前），`student_id` 省略时返回本班次全部记录。
只能查询本人承担班次的记录，其他班次 `403`、不存在的班次 `404`。

### 5.3 验证方式

```powershell
.\.venv\Scripts\python.exe -m pytest member4/test/test_grade_changes.py -q
```

用例覆盖：首次录入 / 修改 / 留空都留痕、按学生过滤、越权与不存在的班次、
页面路径与 REST 路径返回一致、成绩录入入口默认指向上一已完成学期。

## 六、计费接口（教务专用）

| 接口 | 权限 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| `GET /api/v1/registrar/billing/jobs` | 教务 | `semester_id?` | `{"jobs":[{"job_id","semester_id","student_id","amount","course_count","status","retryable","attempts","next_attempt_at","last_error","created_at"}]}` |
| `GET /api/v1/registrar/billing/summary` | 教务 | `semester_id?` | 见下 |
| `POST /api/v1/registrar/billing/dispatch` | 教务 + CSRF | `limit?` | `{"dispatched","sent","failed","abandoned","retrying","results":[]}` |
| `POST /api/v1/registrar/billing/jobs/{job_id}/retry` | 教务 + CSRF | 无 | `{"message","job":{...}}` |

`status` 取值为 `pending / sending / sent / failed`。

`billing/summary` 的字段与"关闭结果与账单状态"页面一致，页面换数据源即可用：

```json
{
  "semester_id": 2, "semester_code": "2026-FALL",
  "billing_status": "PENDING",
  "opened_sections_count": 0, "cancelled_sections_count": 3, "total_enrolled_count": 12,
  "total_amount": 1200.0, "jobs_total": 4, "jobs_sent": 0, "jobs_failed": 0, "jobs_pending": 4,
  "bills": [
    {"bill_id": 1, "student_id": 1, "student_number": "20260001", "student_name": "林航",
     "enrolled_count": 3, "amount": 300.0, "status": "PENDING", "sent_at": null,
     "attempts": 0, "last_error": null}
  ]
}
```

`billing_status` 为 `ALL_SENT` / `PARTIAL_FAIL` / `PENDING`，
`bills[].status` 为 `SENT` / `FAILED` / `PENDING`。金额与选中门数取自关闭事务写入的任务快照，
重试时不会重新计算学费。

### 6.1 发送与重试语义

- 账单任务由成员 1 的关闭事务写入，成员 4 只负责发送、更新状态与重试。
- 发送前先在一个事务里"认领"到期任务（置 `sending` 并把 `next_attempt_at` 顺延一个间隔），
  因此并发调度不会重复发送，进程中途退出也不会丢账单。
- **可重试**：连接失败、超时、408 / 425 / 429 / 5xx，按 `BILLING_RETRY_SECONDS` 间隔持续重试。
- **不可重试**：计费端以 4xx 拒绝账单本身（典型是同一学期同一学生但内容不一致的 409），
  任务置 `failed`、`retryable=false`、`last_error` 以 `[不可重试]` 开头并停止重发。
- 修正外部数据后可用 `POST .../jobs/{job_id}/retry` 重新排队。
- 重复发送同一账单由计费端按 `(学期, 学生)` 唯一键去重，不会重复收费。

## 七、先修检查所需的成绩数据约定

先修判断统一走成员 1 的选课事务实现，成员 4 只暴露同一份数据的查询入口，避免出现第二个口径：

- `passed_course_ids(db, student_id, semester)`：取该学期**开始前**已完成的学期中，
  当前有效的通过成绩（A–D）所在课程集合。
- `completed_course_ids` / `has_passed_course`：教师模块内的等价入口，供页面提示复用。
- 已被更正掉的旧分数不算通过；F、I 与未录入都不满足先修要求。
- 后续成绩更正不自动撤销既有选课，新增选课或替补时重新检查。

## 八、与其它成员的边界

- 认证、会话与角色检查复用成员 3 的实现，成员 4 不另做登录。
- 学期开放、时间冲突、名额与先修判断复用成员 1 的 `registration` 服务，不复制规则。
- 关闭选课与账单任务的创建属于成员 1；成员 4 只消费任务，不修改关闭结果。
- 模板与页面交互属于成员 2；成员 4 只保证接口字段与模板既有用法一致。
