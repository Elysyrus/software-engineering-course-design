# 核心接口约定

所有错误统一返回：

```json
{"detail": "可直接展示给用户的原因"}
```

## 认证与会话

系统不再使用 `X-Role` 或 `X-Subject-ID` 请求头模拟身份。登录成功后，服务器设置两个 Cookie：

- `session_id`：`HttpOnly`、`SameSite=Lax`。它是服务器会话的索引，JavaScript 不能读取。
- `csrf_token`：`SameSite=Lax`、非 HttpOnly。同源前端读取它并放入 `X-CSRF-Token` 请求头，用于所有写操作。

生产环境 Cookie 还会带 `Secure` 属性；开发环境为便于本机 HTTP 调试不设置该属性。会话失效、账号被停用、关联师生档案被停用时，请求返回 `401`。角色不匹配返回 `403`。

首次登录账号的 `must_change_password=true` 时，只能访问改密和退出；其他业务入口返回 `403`。

| 接口 | 请求 | 成功响应 | 说明 |
| --- | --- | --- | --- |
| `POST /api/v1/auth/login` | `{"username": "...", "password": "..."}` | `{"role": "student/teacher/registrar", "is_first_login": true/false}` | 同时设置上述两个 Cookie；不返回密码哈希、会话 ID 或 CSRF 值。账号或密码错误均为 `401`。 |
| `POST /api/v1/auth/change-password` | `{"old_password": "...", "new_password": "..."}` + `X-CSRF-Token` | `{"message": "密码修改成功，请重新登录"}` | 当前会话必须有效；旧密码错误为 `400`，新密码不合规则为 `422`。改密后撤销该账号全部旧会话并清除 Cookie。 |
| `POST /api/v1/auth/logout` | `X-CSRF-Token` | `{"message": "已退出登录"}` | 撤销当前会话并清除 Cookie；重复退出保持可安全调用。 |

前端调用写接口时应通过浏览器自动携带 Cookie，并将 `csrf_token` Cookie 的值复制到 `X-CSRF-Token`。不得把权限 Token、角色或密码写入 `localStorage`。

## 教务人员管理

以下接口均要求已登录的 `registrar` 角色。除 `GET` 外，全部必须携带当前会话对应的 `X-CSRF-Token`。路径参数 `{account_id}` 是 `accounts.id`，不是学号、工号或学生/教师档案 ID。

| 接口 | 请求/响应 | 说明 |
| --- | --- | --- |
| `GET /api/v1/admin/users` | 返回用户数组 | 仅返回学生、教师的公开资料：`id`、`username`、`full_name`、`role`、`department`、`is_active`。 |
| `POST /api/v1/admin/users` | `{"full_name":"...","role":"student"}`；教师额外有非空 `department` | 自动生成学生学号或教师工号，初始密码为 `Initial123`，响应 `201` 并返回 `id`、`login_number`、`role`。 |
| `GET /api/v1/admin/users/{account_id}` | 返回一条公开资料 | 不存在或不是师生账号返回 `404`。 |
| `PATCH /api/v1/admin/users/{account_id}` | `{"full_name":"..."}`；教师可额外传 `department` | 更新档案资料。学生不能传 `department`，否则 `422`。 |
| `PATCH /api/v1/admin/users/{account_id}/status` | `{"is_active": true/false}` | 启停账号与关联档案；停用会撤销现有会话。 |
| `POST /api/v1/admin/users/{account_id}/reset-password` | 无请求体 | 密码重置为 `Initial123`，强制下次登录改密，并撤销现有会话。 |
| `DELETE /api/v1/admin/users/{account_id}` | 返回 `{"action":"deleted/deactivated", "message":"..."}` | 没有选课/成绩/账单（学生）或开课（教师）历史时物理删除；否则保留历史并停用。 |

## 学生方案

- `GET /semesters/{semester_id}/schedule`：读取当前学生的草稿、正式主选、正式备选和版本。
- `PUT /semesters/{semester_id}/schedule/draft`：保存完整草稿，不占名额。
- `POST /semesters/{semester_id}/schedule/submit`：把当前草稿整体提交。
- `DELETE /semesters/{semester_id}/schedule/offerings/{offering_id}`：单独退课。
- `DELETE /semesters/{semester_id}/schedule`：确认后删除整份方案。

保存草稿请求示例：

```json
{
  "expected_version": 1,
  "choices": [
    {"offering_id": 11, "kind": "primary"},
    {"offering_id": 12, "kind": "primary"},
    {"offering_id": 13, "kind": "primary"},
    {"offering_id": 14, "kind": "primary"},
    {"offering_id": 15, "kind": "alternate", "alternate_priority": 1},
    {"offering_id": 16, "kind": "alternate", "alternate_priority": 2}
  ]
}
```

提交、退课和删除请求只需当前版本：

```json
{"expected_version": 2}
```

成功后响应给出新 `version`。页面必须保存新版本；收到 `409` 和“重新载入”提示时重新获取方案。

## 教务关闭

- `POST /registrar/semesters/{semester_id}/close`

响应包含取消班次 ID 和本次创建的账单任务数。关闭成功不代表外部计费已收到；成员 2 应单独展示 `BillingJob.status`，成员 4 负责发送状态接口与重试器。

## 集成约束

- 成员 2：不要根据页面剩余名额自行判定提交成功，以后端结果为准。
- 成员 3：每次请求都检查账号当前状态；不要信任请求体中的学生 ID。
- 成员 4：成绩通过值为 A-D；先修检查只读取当前有效成绩。账单发送使用任务中的金额和 JSON 快照，不重新查询并计算。
- 所有修改学期/班次的业务入口遵守“学期 -> 业务主体 -> 班次 ID 升序”的锁顺序。
