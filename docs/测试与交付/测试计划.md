## 6. 执行方法

```bash
# MySQL 专用测试库（库名以 _test 结尾）
export MYSQL_TEST_DATABASE_URL='mysql+pymysql://用户:密码@127.0.0.1:3306/course_registration_test?charset=utf8mb4'
export ACCEPTANCE_DATABASE_URL='mysql+pymysql://用户:密码@127.0.0.1:3306/course_acceptance_test?charset=utf8mb4'

# 1. 开发者自动化测试
.venv/bin/python -m pytest -q -rs

# 2. 接口级验收（自动清空验收库、启动临时系统，耗时随操作系统和故障连接等待变化，Windows 可超过 1 分钟）
.venv/bin/python "docs/测试与交付/验收工具/run_acceptance.py"

# 3. 最后一个名额竞争复测
.venv/bin/python "docs/测试与交付/验收工具/reproduce_last_seat_race.py" --rounds 30

# 4. 页面手工验收
.venv/bin/python -m scripts.run_demo --database-url 'mysql+pymysql://用户:密码@127.0.0.1:3306/course_registration?charset=utf8mb4'
```

Windows 下把 `.venv/bin/python` 换成 `.\.venv\Scripts\python.exe`，`export` 换成 `$env:变量名='值'`。

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 误用业务库执行测试导致数据被清空 | 测试和验收脚本都只接受以 `_test` 结尾的库名 |
| 验收依赖本机端口 | 脚本支持 `--port` 等参数 |
| 演示数据与验收数据混用导致结果不可复现 | 验收每次清空重建专用库 |
| 一次执行通过掩盖偶发问题 | 并发与时间相关用例重复执行多次，结果写入缺陷记录 |
