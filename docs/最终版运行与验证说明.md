## 安装与完整启动

在解压后的项目根目录打开 PowerShell，使用 Python 3.12 或更高版本：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.run_demo
```

已经有 `.venv` 时直接执行第三条。该命令升级数据库、初始化演示数据，启动主应用、只读目录、计费接收端、账单重试进程。打开 `http://127.0.0.1:8000/login`。停止时在启动终端按 Ctrl+C；脚本只停止自己启动的子进程。再次运行保留原有数据库、密码、选课和成绩。

| 角色 | 演示账号 | 初始密码 |
| --- | --- | --- |
| 教务 | `registrar` | `Initial123` |
| 学生 | `S001`–`S010` | `Initial123` |
| 教师 | `T001`–`T010` | `Initial123` |

第一次登录必须改密。已有账号的密码不会因再次初始化而重置。所有人员姓名、社会保障号码等演示资料均为虚构。

默认 SQLite 用于方便每位组员本机复现；它不能验证 MySQL 的行锁并发。生产式课程演示或并发验收可连接 MySQL 8：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_demo --database-url 'mysql+pymysql://用户名:密码@127.0.0.1:3306/数据库名?charset=utf8mb4'
```

需提前创建数据库并授予账号该库的权限；账号密码以本机实际配置为准，不要提交到 GitHub。普通服务器运行可按 `.env.example` 配置后分别启动主应用和三个配套进程，关闭数据库连接字符串的示例占位符。

端口被占用时可使用 `--port 8900 --catalog-port 8911 --billing-port 8912`。日志在 `tmp/run-demo-端口/`。独立计费账本默认 `mock_billing.db`，可通过 `--billing-database 路径` 为不同演示环境分开保存。单独启动计费服务时，设置 `MOCK_BILLING_DATABASE` 才启用持久账本；不设置时保留原模块的内存测试模式。

## 主要流程

1. 三位学生分别登录并改密。在目录将前四门设为主选、后两门设为备选；进入草稿页调整备选顺序，保存，刷新后确认仍保留，再提交。
2. 正式结果显示真实选中班次及备选；选课开放时可以单独退课或确认删除整份方案。后续修改允许 0–4 主选、0–2 备选。旧页面版本不匹配会提示重载。
3. 教师进入班次认领页，可取消或认领具备资格且无时间冲突的班次；花名册只显示真实正式选上的学生。成绩页默认上一已完成学期，录入、修改或留空均经权限校验并记录实际变化。
4. 教务管理页可以维护姓名、出生日期、虚构社会保障号码、档案状态、教师院系和学生毕业日期，另有账号启停、重置密码和删除功能。有历史数据时删除转为停用。
5. 教务选择真实学期，输入 `CLOSE-CONFIRM` 并二次确认。系统处理无教师和不足三人的班次、两轮备选及账单快照；页面显示数据库中的关闭结果。
6. 后台重试进程发送账单，状态页定期刷新。关闭成功与外部发送成功分开显示。失败后可恢复外部服务自动重试；明确内容冲突等不可重试错误需先处理，再点击“重新排队”。独立计费账本在进程重启后仍按学期、学生去重。

初始开放学期有八门互不冲突课程，每班上限十人，各有教师，满足首次 4+2 演示；初始没有伪造的学生选课。历史学期包含三位学生的成绩供教师修改和学生查询。运行数据统一由 `scripts/seed_final_demo.py` 初始化（启动脚本已调用）。原模块测试需要的独立场景移入 `tests/support/`，不会参与应用启动。

## 业务实现约定

- 页面操作全部调用真实数据库与统一服务，没有全局模拟学生草稿或写死“全部发送成功”。外部目录、计费服务本身仍是明确命名的模拟系统。
- 外部目录是只读 JSON 服务。注册库按课程代码、学期代码和班号进行映射，不依赖外部编号充当本地班次 ID。实时教师与人数来自注册库，目录描述来自外部查询；请求超时三秒，故障显示不可用，不伪造结果。
- `python -m scripts.sync_catalog` 可从运行中的外部目录显式初始化新学期的本地镜像；已关闭学期不重新同步，已有业务数据不会被目录查询覆盖。外部 JSON 的维护属于外部服务管理员，不由注册网页写入。
- “关闭选课”不等于“学期已完成”。已关闭注册且学期结束日期已过，才可作为完成学期录入成绩/满足先修要求；日期按北京时间判断。
- MySQL 事务按学期、业务主体、班次顺序取得锁，锁后重读最新对象；名额检查使用当前读，防止 REPEATABLE READ 旧快照导致超额。关闭遇活动事务返回可重试提示。
- 初次提交需恰好 4+2；原正式结果与草稿分离，失败不覆盖原结果；未改变的重复提交不改变排队时间。主动退课不自动补回。
- 所有业务写入口检查角色和 CSRF；身份由 HttpOnly Cookie 对应服务端会话确定。页面对外部字符串转义，人员姓名中的 HTML 当作文本显示。
- 固定学费与课表快照在关闭事务中保存；发送器不重算费用。人员编号使用锁定序列分配，不因删除记录而复用。

## 本轮实际验证

自动化回归命令：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

未配置 MySQL 测试库时，当前六项真实 MySQL 用例会跳过。配置专用测试库后运行完整回归：

```powershell
$env:MYSQL_TEST_DATABASE_URL='mysql+pymysql://用户名:密码@127.0.0.1:3306/独立库_test?charset=utf8mb4'
.\.venv\Scripts\python.exe -m pytest -q
```

**这些 MySQL 测试会创建和删除测试表，必须用名称以 `_test` 结尾的专用空库，禁止业务库。**
