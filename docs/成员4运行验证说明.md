整理：成员 4

适用分支：`member4`（同时适用于 `integration`）

本文档给出从零开始运行整个系统、并验证成员 4 功能是否正确的完整步骤。所有命令均在项目根目录
`E:\software-engineering-course-design` 下执行。

## 一、环境准备

### 1.1 Python 版本

项目要求 Python 3.12（`requirements.txt` 中的 `pydantic-settings`、`pytest` 等依赖需要 3.9 以上，
本机若同时装有 3.8 请勿使用）：

```powershell
py -0p                 # 查看已安装的解释器
py -3.12 --version     # 确认 3.12 可用
```

### 1.2 创建虚拟环境并安装依赖

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 1.3 配置文件

```powershell
Copy-Item .env.example .env
```

`.env` 中只需要两个键：

```text
DATABASE_URL=sqlite:///./course_registration.db
APP_ENV=development
```

- **SQLite（推荐，零依赖）**：使用上面的写法，数据库文件就是项目根目录下的 `course_registration.db`。
- **MySQL（可选）**：改成 `mysql+pymysql://用户:密码@127.0.0.1:3306/库名?charset=utf8mb4`，
  并先手工建库。未安装 MySQL 时不要使用这行，否则启动会连接失败。

计费相关的可选配置（不写就用默认值）：

```text
BILLING_SERVICE_URL=http://127.0.0.1:8082   # 计费模拟服务地址
BILLING_RETRY_SECONDS=30                    # 单条账单两次尝试之间的最小间隔
BILLING_REQUEST_TIMEOUT_SECONDS=5           # 单次发送超时
```

`DATABASE_URL` 也可以用环境变量临时覆盖，便于在不影响演示库的前提下试验：

```powershell
$env:DATABASE_URL = 'sqlite:///./course_registration_test_run.db'
```

## 三、初始化账号与演示数据

按顺序执行，三个脚本都可以重复运行，已存在的数据不会被覆盖：

$env:INITIAL_REGISTRAR_PASSWORD = 'Initial123'

.\.venv\Scripts\python.exe -m scripts.seed_demo_data

可以直接演示"关闭 → 生成账单 → 发送 → 失败重试"。

## 四、启动服务

开四个终端，分别执行（主服务、计费模拟服务与计费重试进程是验证成员 4 功能必需的，
课程目录模拟服务可选）：

```powershell
# 终端 1：主应用
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# 终端 2：计费模拟服务（账单发送与重试验证）
.\.venv\Scripts\python.exe mock_billing/mock_billing_service.py --port 8082

# 终端 3：课程目录模拟服务（成员 2 的只读目录）
.\.venv\Scripts\python.exe mock_catalog/mock_catalog_service.py --port 8081

# 终端 4：计费后台重试进程（失败账单按间隔自动补发，需要常驻）
.\.venv\Scripts\python.exe -m scripts.billing_retry_worker
```

计费重试进程每 5 秒轮询一次到期任务（`--interval` 可调，`--once` 只跑一轮）；
单条账单最早何时重发由 `BILLING_RETRY_SECONDS` 决定（默认 30 秒）。
没有这个进程时，账单只会在调用 `POST /api/v1/registrar/billing/dispatch` 时发送一次，
失败后不会自动恢复。

健康检查：

```powershell
curl.exe -sS http://127.0.0.1:8000/health        # {"status":"ok"}
curl.exe -sS http://127.0.0.1:8082/billing/charges  # {"count":0,"charges":[]}
curl.exe -sS http://127.0.0.1:8081/catalog/courses  # 课程目录 JSON
```

接口文档：<http://127.0.0.1:8000/docs>。文档中共 29 条路径，其中成员 4 的 23 条
（REST 风格、页面兼容与计费接口，共 26 个操作）、成员 1 的 6 条；成员 2 的页面模拟接口
设置为不进入文档，但可正常调用。

停止全部服务：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'uvicorn|mock_billing|mock_catalog|billing_retry_worker' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

### 5.1 自动化测试（最快）

.\.venv\Scripts\python.exe -m pytest member4 -q    # 期望 118 passed, 1 skipped

### 5.2 接口验证

两种方式，任选其一：

1. **Swagger UI**：打开 `/docs`，先用 `POST /api/v1/auth/login` 登录（浏览器会自动保存 Cookie），
   再从浏览器 DevTools 的 Cookie 里复制 `csrf_token` 填到写请求的 `X-CSRF-Token` 头。
2. **Apifox / Postman**：导入 `member4/成员4接口测试集合.postman_collection.json`，
   按文件夹顺序执行（登录后 CSRF 与班次 id 由脚本自动捕获）。负向用例已带响应示例，
   重新导入时请选择「覆盖已有接口」，详见 `member4/成员4接口测试文档.md`。

| --- | --- | --- | --- |

### 5.4 计费链路验证

先停掉计费模拟服务，再按顺序执行：

1. 教务关闭开放学期（`POST /registrar/semesters/{id}/close`）：返回
   `billing_jobs_created=4`，三个未认领班次被取消，4 名学生各产生 300.00 元账单；
2. `GET /api/v1/registrar/billing/summary`：`billing_status=pending`，
   4 条 `pending` 账单带学号、姓名、选中 3 门、金额 300.00；
3. `POST /api/v1/registrar/billing/dispatch`：计费服务不可用，4 条任务变 `failed`，
   `last_error` 记录连接被拒，`retryable=true`；再查 summary 为 `partial_fail`；
4. 启动计费模拟服务，等一个重试间隔后运行后台重试进程（或再派发一次）：
   4 条任务自动补发成功，`attempts` 变为 2，summary 变为 `all_sent`，
   `GET http://127.0.0.1:8082/billing/charges` 可看到 4 条 300.00 元账单；
5. 用 `POST http://127.0.0.1:8082/billing/charges` 给某个 `(学期, 学生)` 预置一条
   金额不同的账单制造 409 冲突，再派发：该任务变 `failed` 且 `retryable=false`、
   `last_error` 以 `[不可重试]` 开头；等一个间隔后再派发仍是 `dispatched=0`，
   不会无限重发；
6. 修正外部账单内容后可调用 `POST /api/v1/registrar/billing/jobs/{job_id}/retry`
   把它重新排队，下一轮重试会再次发送。

### 5.5 关键规则核对

- [ ] 无授课资格不能认领（403）；时间冲突不能认领（409）；已被他人认领不能抢占（409）
- [ ] 学期关闭后不能认领、取消或修改成绩
- [ ] 成绩只能录入已完成学期，只能录入本班学生，非法等级被拒（422）
- [ ] 首次录入 / 修改 / 留空都会写入成绩变更记录（含前后值、操作教师、时间），
      可通过 `GET /api/v1/teacher/offerings/{id}/grade-changes` 查询
- [ ] 学生只能看到自己的成绩，A–D 通过
- [ ] 未登录 401、角色越权 403、写请求缺少 CSRF 403
- [ ] 重复发送同一账单不重复收费；内容冲突返回 409 并留档
- [ ] 可重试失败（连接失败 / 超时 / 5xx / 429）按间隔自动重试并最终 `sent`
- [ ] 不可重试失败（4xx 拒绝）停止重发，只能人工 `retry` 重新排队

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动时报数据库连接失败 | `.env` 里仍是 MySQL 写法但本机没有 MySQL，改成 SQLite |
| 业务接口返回 403「首次登录必须先修改密码」 | 该账号还没改初始密码，先在页面完成改密 |
| 写请求返回 403「缺少 CSRF 令牌」 | 请求没带 `X-CSRF-Token`；页面由 `app.js` 自动带，接口工具需手动配置 |
| 创建 venv 后装依赖失败 | 解释器版本低于 3.9，改用 `py -3.12` 重建 |
| 端口被占用 | 8000/8081/8082 之一已在运行，先按第四节的停止命令清理，或换端口启动 |
| 关闭选课后账单一直是 `pending` | 计费重试进程（终端 4）没有启动；启动后会自动补发，也可手动调用 `POST /api/v1/registrar/billing/dispatch` |
| 账单状态一直是 `failed` 且 `retryable=false` | 计费端拒绝了账单内容（例如同键金额不一致），需要先修正外部账单，再调用 `.../jobs/{id}/retry` 重新排队 |
| 演示数据被测试改乱 | 重新执行第三节的种子脚本可重建既有数据；`claimable-sections` 的班次归属需按测试文档恢复，或删库重建 |
| `pytest -m mysql` 被跳过 | 未配置 `MYSQL_TEST_DATABASE_URL`，需要名称以 `_test` 结尾的专用库 |
