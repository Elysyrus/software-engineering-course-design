# 成员 3 模块总结：认证与人员账号管理

更新时间：2026-09-13
负责范围：账号认证、服务端会话、权限隔离、师生账号与档案管理、教务初始化与演示数据。

## 1. 模块结论

成员 3 的核心模块已经完成：系统现在通过数据库中的 `accounts` 和 `server_sessions` 进行真实登录，不再依赖前端保存 Token 或请求头伪造角色。学生、教师、教务的页面入口均有身份与角色限制；教务可管理学生、教师的账号和基础档案。

当前完整测试结果：`53 passed, 1 skipped`。

跳过的一项是需要专用 MySQL 测试库的并发测试；本机未配置 `MYSQL_TEST_DATABASE_URL` 时会正常跳过。

## 2. 已实现功能

### 2.1 数据模型与迁移

| 内容                                    | 作用                                                                      |
| --------------------------------------- | ------------------------------------------------------------------------- |
| `Account` / `accounts`              | 保存登录编号、角色、密码哈希、启停状态、首次改密标记、关联学生或教师 ID。 |
| `ServerSession` / `server_sessions` | 保存服务端会话 ID、CSRF Token、创建时间、到期时间和撤销时间。             |
| Alembic 迁移                            | 将账号与会话表纳入数据库升级流程。                                        |

角色统一为：`student`、`teacher`、`registrar`。

### 2.2 认证与会话

认证服务位于 `app/services/auth.py`。

- 密码强度校验、Argon2 密码哈希和密码验证。
- 创建账号；登录编号重复时拒绝创建。
- 真实登录：账号不存在与密码错误统一返回 `401`，避免泄露账号是否存在。
- 创建随机服务端 Session 与 CSRF Token。
- 校验会话是否存在、过期、撤销，且每次请求检查账号是否启用。
- 学生、教师账号还会检查关联档案的 `active` 状态。
- 修改密码会验证旧密码、写入新哈希、解除首次改密状态，并撤销该账号所有旧会话。
- 退出登录撤销当前会话；重复退出可安全调用。
- CSRF 值校验：缺失或错误均返回 `403`。

### 2.3 Cookie、首次改密与角色限制

认证依赖位于 `app/auth_contract.py`，认证 Web 路由位于 `web/web_routes.py`。

```text
浏览器 session_id Cookie
  -> current_account()
  -> get_session_account()
  -> CurrentUser(role, subject_id)
  -> require_student / require_teacher / require_registrar
```

- 登录响应设置 `HttpOnly session_id` Cookie；JavaScript 无法读取会话 ID。
- 同时设置可读取的 `csrf_token` Cookie；前端写请求把它放进 `X-CSRF-Token`。
- 生产环境 Cookie 使用 `Secure`，开发环境为方便本机 HTTP 调试不使用。
- `must_change_password=true` 的首次登录账号，只能进入改密或退出流程；普通学生、教师、教务页面会被拒绝。
- 学生只能进入 `/student/*`，教师只能进入 `/teacher/*`，教务只能进入 `/admin/*`。

### 2.4 师生人员与账号管理

人员服务位于 `app/services/personnel.py`。

- 按年份生成登录编号：学生如 `20260001`，教师如 `T20260001`。
- 创建学生或教师时，在同一事务中创建人员档案与关联账号。
- 学生、教师的查询、资料修改和启用/停用。
- 停用人员时同步停用账号并撤销其全部会话。
- 教务用户管理：人员列表、单人详情、创建、修改、重置密码、启停、删除。
- 重置密码后设置 `must_change_password=true`，并撤销旧会话。
- 删除人员前检查业务历史：
  - 学生已有选课方案、成绩或账单任务时，保留历史并停用。
  - 教师已有开课记录时，保留历史并停用。
  - 没有业务历史时，删除人员、账号及会话。
- 写操作使用统一事务边界：任何一步异常都会 `rollback()`，不会留下半完成数据。

### 2.5 Web 页面与 API

已完成真实 API：

| 类别         | 接口                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| 认证         | `POST /api/v1/auth/login`、`POST /api/v1/auth/change-password`、`POST /api/v1/auth/logout`            |
| 教务人员管理 | `GET/POST /api/v1/admin/users`                                                                            |
| 教务人员管理 | `GET/PATCH/DELETE /api/v1/admin/users/{account_id}`                                                       |
| 教务人员管理 | `PATCH /api/v1/admin/users/{account_id}/status`、`POST /api/v1/admin/users/{account_id}/reset-password` |

教务“师生账号与档案管理”页面已接入真实接口，支持：创建、列表、编辑资料、重置密码、启用/停用、删除人员。

### 2.6 初始化与演示数据

| 脚本                          | 命令                                                          | 功能                                                                        |
| ----------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `scripts/init_registrar.py` | `python -m scripts.init_registrar --login-number registrar` | 创建或复用唯一教务账号；不会覆盖已存在账号的密码。                          |
| `scripts/seed_demo_data.py` | `python -m scripts.seed_demo_data`                          | 补充 10 名随机姓名的演示学生、10 名随机姓名的演示教师、3 门演示课程；可重复执行，不覆盖已有记录。 |

演示脚本中新建师生的初始密码均为 `Initial123`；首次登录后必须修改。教务初始密码由终端安全输入，或从 `INITIAL_REGISTRAR_PASSWORD` 环境变量读取。
